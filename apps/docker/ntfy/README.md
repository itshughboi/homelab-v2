# ntfy

**URL:** https://ntfy.hughboi.cc
**Docs:** https://docs.ntfy.sh/

Self-hosted push notification server. The central notification hub for the entire
homelab — Prometheus Alertmanager, Gatus, Gitea CI, most Ansible playbooks, Vaultwarden
backup validation, changedetection.io, and anything else that supports ntfy or HTTP
webhooks. See [Topics in Use](#topics-in-use) for the full, subscribe-ready list.

## Stack

Single container.

## Config

The server config is at `./server.yml` in the service directory, mounted at `/etc/ntfy/server.yml:ro`.

Key settings to configure in `server.yml`:
```yaml
base-url: https://ntfy.hughboi.cc
listen-http: :80
cache-file: /var/cache/ntfy/cache.db
cache-duration: 12h
auth-file: /var/cache/ntfy/auth.db
auth-default-access: deny-all   # require auth on all topics
behind-proxy: true
```

## Volumes

| Mount | Purpose |
|---|---|
| `cache` (named volume) | Message cache DB and auth DB |
| `./server.yml:/etc/ntfy/server.yml:ro` | Server configuration |

## Topics in Use

Every ntfy topic published to anywhere in this repo. **Subscribe to all of these on a
new device** to receive the full set of homelab notifications. (Auto-generated by
grepping `ntfy.hughboi.cc/<topic>` across the repo; excludes decommissioned
`apps/docker/sunset/` and placeholder examples. Keep it in sync when adding a topic.)

| Topic | What sends to it | Where it's configured |
|---|---|---|
| `homelab` | The catch-all: most Ansible playbooks (image update/prune, volume-backup, disk-health/usage, PBS/NFS/SSL/time-sync checks, k3s upgrades, etcd backup, Proxmox snapshots/updates, backup-verify, host bootstrap, journal/postgres maintenance, lynis) | `ansible/playbooks/**/main.yaml` |
| `alertmanager` | Prometheus Alertmanager (fires on every alert; also goes to Discord + SMTP) | `apps/docker/promgraftail/prometheus/alertmanager.yml` |
| `ci` | Gitea CI failures (red pipeline — GitHub emails natively, this is the Gitea parity) | `.gitea/workflows/ci.yaml` |
| `gatus` | Gatus uptime/status-page health checks | `apps/docker/gatus/config/config.yaml` |
| `n8n` | Vaultwarden backup validation success/failure | `ansible/playbooks/vaultwarden/backup-validation.yml`, `group_vars/vaultwarden_host.yml` |
| `change-detection` | changedetection.io website-change alerts | `apps/docker/change-detection/` |
| `unifi` | UniFi filebrowser rsync job results | `ansible/playbooks/unifi/rsync-filebrowser.yaml` |
| `apprise` | Mailrise → ntfy bridge (email-to-push gateway). **Requires auth** (`ntfys://user:pass@`) | `apps/docker/mailrise/mailrise.conf` |

> Most topics are anonymous publish/subscribe. `apprise` is the exception — it's
> published to with credentials via mailrise, so subscribing may require a user with
> read access on that topic (see Auth / Access Control below).

## Subscribing on Mobile

Install the ntfy app ([Android](https://play.google.com/store/apps/details?id=io.heckel.ntfy) / [iOS](https://apps.apple.com/app/ntfy/id1625396347)):

1. Open the app → **+** → **Custom server** → `https://ntfy.hughboi.cc`
2. Subscribe to each topic in the table above. The essentials for a phone are
   `homelab`, `alertmanager`, and `ci`; add the rest for full coverage.
3. If a topic requires auth (e.g. `apprise`), enter credentials in the subscription.

## Sending a Test Notification

```sh
curl -d "Test message" https://ntfy.hughboi.cc/homelab
# With auth:
curl -u "username:password" -d "Test message" https://ntfy.hughboi.cc/homelab
```

## Auth / Access Control

To add users (from inside the container):
```sh
docker exec -it ntfy ntfy user add --role=admin hughboi
docker exec -it ntfy ntfy user add --role=user myapp
docker exec -it ntfy ntfy access myapp homelab rw   # grant myapp read+write on 'homelab'
```

## Upgrade Notes

- The `cache` named volume holds both the message cache and the user auth database. Back it up before upgrading.
- Check the [ntfy changelog](https://github.com/binwiederhier/ntfy/releases) for config format changes between versions.

## Troubleshooting

**Mobile app not receiving notifications:**
1. Confirm the topic name is correct (case-sensitive)
2. Check `docker logs ntfy` for delivery errors
3. If using auth, verify the app is configured with valid credentials

**Notifications arriving with delay:**
- ntfy uses long-polling. If behind a proxy, ensure `behind-proxy: true` is set in `server.yml` and that Traefik isn't buffering connections.
